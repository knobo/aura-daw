# MIDI Slice 2 — Input Routing, Recording, Clock/Sync Out Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use
> `superpowers:subagent-driven-development` (recommended) or
> `superpowers:executing-plans` to implement this plan task-by-task. Steps use
> checkbox (`- [ ]`) syntax for tracking. Execution mode is the owner's call at
> run start and is recorded in the execution note at the bottom of this file.

**Goal:** Make a connected MIDI keyboard actually *play and record into the
project* — incoming notes routed to a chosen track's real instrument through
the RT graph, a take registered as ONE `Actor::Engine` transaction at stop —
and make AURA drive external gear: MIDI clock + Start/Stop/Continue/SPP out
(Hydrogen sync) **and** note-out from a chosen MIDI track to an external
synth.

**Architecture:** Three seams, none of which puts new state in the document.
(1) **In-routing**: a process-global `MidiInHub` owns a wait-free SPSC ring
from the (non-RT) midir callback thread to the RT output callback; the mixer
dispatches the drained events into the target track's existing
`LiveNodeCell`, so monitoring uses the *same* PolySynth/Sampler/plugin node
playback uses. (2) **Recording**: the same hub buffers timestamped note edges
control-side while a take runs; at stop the engine converts them to ticks
through the same `TempoMap` bijection playback schedules from and applies
`Op::MidiClipAdd` **inside the existing `commit_recording_finalize`
transaction** — "the op is the registration, never the recording itself".
(3) **Out**: a dedicated, non-RT `aura-midi-out` thread reads
`SharedRt::{playing,position}` + a `TempoMap`/event snapshot and writes MIDI
clock, transport messages and note events to a `midir` output port — it never
touches `engine.rs` at all.

**Tech Stack:** Rust (`src-tauri/`: midir 0.11, rtrb 0.3, parking_lot 0.12,
serde), TypeScript/Svelte 5 (`src/lib/`), vitest.

**Spec:** `docs/backlog/hardware-midi-io.md` (the owner's requirements + the
post-Plan-E design notes and the suggested cut this slice implements: items
2, 3, 4 and 5). Scope definition: `next-prompt.md` §3 "Track B". Standing
constraints: `next-prompt.md` §2. Inherited rulings: `docs/PHASE4-PLAN.md`
"Plan E handoff" (especially Task 13's `Actor::Engine` take-transaction
pattern and the transport-family transient rule). Slice 1's landed shape:
`src-tauri/src/midi_input.rs` + `docs/midi-input.md`.

## Global Constraints

Every task's requirements implicitly include this section.

- **The op log is ON.** `journal.ndjson` is a persisted format;
  `OP_FORMAT_VERSION` is **2**. This plan adds **no new op kind and changes no
  op shape** — it reuses `Op::MidiClipAdd` and `Op::ClipAdd` exactly as they
  landed, so the version stays 2 and no dual-shape reader is needed. Additive
  `#[serde(default)]` fields on an op or on `TxMeta` would stay non-breaking;
  anything else needs a bump **and** a reader that understands both shapes.
- **Thin renderer (ADR 0006).** Every frontend change in this plan is command
  emission or UI chrome. No new authoritative state, no business logic, no
  time math frontend-side.
- **Frozen command/event names stay frozen; bodies become wrappers; new
  commands are additive.** Frozen-name bodies touched here:
  `midi_select_input_port`, `midi_input_status` (slice 1) — names kept,
  bodies re-routed through `ControlPlane`. New additive commands:
  `midi_select_input_track`, `midi_list_output_ports`,
  `midi_select_output_port`, `midi_set_clock_enabled`,
  `midi_select_output_track`, `midi_output_status`.
- **`transact` closures must not panic** (no panic rollback until Plan F).
  Validate before mutating, every time. In particular: the take's target
  track is validated to still exist **before** the op is built
  (prepare-outside), never inside the closure by unwrapping.
- **Prepare-outside / commit-inside.** Unbounded work (TempoMap build,
  sample→tick conversion, note pairing, WAV finalize) happens before the
  transaction; the transaction is a short apply. **No blocking engine
  round-trips inside a transaction.**
- **The M-3 redo invariant.** A transient write must never touch a document
  field an entry's `ops` can address. `debug_assert_transient_invariant` in
  the commit path enforces it in debug builds (transient batches may address
  only `ObjectRef::Transport`, unless the batch is a mid-gesture fold). This
  plan adds **no new transient transaction**; the take registration is
  non-transient. Checked explicitly in the self-review section below.
- **Gesture lock order is gesture-before-session, everywhere.** This plan adds
  no gesture-shaped commit path; where it takes locks, the order is
  session-then-tables [C1], never the reverse, and no lock is ever held across
  an `EngineHandle::request`.
- **RT discipline (ARCHITECTURE §2.1).** No allocation, no locks, no I/O on
  the audio callback path. The MIDI-in ring is `rtrb` SPSC; the RT side pops
  into a **preallocated fixed-size array**. The midir callback thread and the
  `aura-midi-out` thread are *not* RT threads — a `parking_lot::Mutex` and a
  heap `Vec` are allowed there, and the ALSA write happens there, never in the
  audio callback.
- **Foreground, `timeout`-guarded test runs only:**
  `timeout 900 cargo test --manifest-path src-tauri/Cargo.toml` and
  `timeout 300 npx vitest run`. Never background a suite and move on.
- **Baseline at branch base (`3340aa8`, verified 2026-08-14 in this
  worktree): 527 backend + 206 frontend, all green.** README.md:389 and
  CONTRIBUTING.md:62 still say **506** — PR #17 (slice 1) added its tests
  without updating the dated counts. Task 1 corrects that (see ruling 13).
- **Dated test-count convention:** README.md + CONTRIBUTING.md carry the
  count with the date. Per ruling 13 this plan updates them in Task 1
  (correction) and Task 12 (final), not in every task.
- **Hardware-free tests.** Everything in this plan is unit-testable without a
  MIDI device: pure functions, injected hubs/sinks, and — where a real
  `midir` connection is unavoidable — ALSA **virtual** ports
  (`midir::os::unix::{VirtualInput, VirtualOutput}`, both present in midir
  0.11; slice 1 already uses `VirtualInput` this way) with a graceful
  `eprintln!("skipping: …"); return;` when the sandbox has no
  `/dev/snd/seq`. Steps that genuinely need hardware are marked
  **OWNER-VERIFY** and are never faked.

## Scope rulings (decided now, marked per ADR 0007, so no task stalls)

1. **The MIDI-in target track is app config, not document state.** It goes
   behind a `ControlPlane` method with attribution logging and **no op** —
   the same §4.5 config carve-out as `select_input_device`/
   `select_output_device` (inventory row 29). The backlog says "routed … to
   the armed track's instrument"; `TrackState.armed` *is* document state with
   its own op, and deriving the routing target from it would mean every
   `armed` write path (commands, undo/redo, project open, MCP) has to
   re-publish the target — a side-channel by construction. So `armed` stays
   the record-arm document flag, the routing target is a separate app-config
   selection, and the **frontend** calls the additive selection command from
   the same arm click on a `kind: "midi"` track so the UX still reads
   "arm a track, play it". Deviation from the backlog wording, recorded.
2. **Exactly one monitoring path is ever live.** With a target track set,
   incoming notes route to that track's instrument through the RT graph and
   the slice-1 preview tone is NOT used. With no target set, slice 1's
   preview-grade tone behaves exactly as documented today. Never both (no
   doubled sound), never neither (no silent regression for slice-1 users).
3. **MIDI-out needs no `engine.rs` diff at all.** Clock, transport messages
   and note-out run on their own `aura-midi-out` thread over `SharedRt`
   atomics + a `TempoMap`/event snapshot. This is why the owner's
   high-priority half of this slice is *not* gated on the orchestrator's
   one-engine.rs-task-at-a-time rule (see Execution notes).
4. **The clock's musical position is `SharedRt::position` + the `TempoMap`
   bijection, not `SharedRt::steady`.** `steady` never stops, never seeks and
   never wraps — it cannot express Start/Stop/Continue/SPP, which are exactly
   what Hydrogen sync is. Sub-block pacing is wall-clock interpolation
   **re-anchored on the observed transport position**, so long-run rate is the
   engine's, not the OS's. The `SectionTable` is not used: it is a
   precomputed accelerator over the *same* `TempoMap` bijection and buys
   nothing at 24 PPQN. Deviation from the backlog's "steady clock" wording,
   recorded.
5. **A backward transport jump (loop wrap or backward seek) resyncs the
   slave** with `Stop` + `SongPosition` + `Continue` rather than free-running
   the clock. Chosen so a looped section re-cues Hydrogen on the downbeat;
   the alternative (silent re-anchor, correct tempo but drifting bar phase)
   is recorded here as the thing to switch to if the owner's Hydrogen
   dislikes the re-cue.
6. **One take = one transaction.** The audio `ClipAdd`s and the MIDI
   `MidiClipAdd` ride in the SAME non-transient `Actor::Engine` transaction
   (`commit_recording_finalize`), so a take is one undo entry. The
   `TransportState = "stopped"` `Set` stays its own transient commit — Plan E
   Task 13's review ruling (Important-1), carried forward unchanged.
7. **Explicit `kind: "midi"` track ids are filtered out of the audio record
   set.** Today `Control::start_recording` would hand a midi track to the WAV
   writer and produce an audio clip on it. Slice 2 splits targets by kind:
   audio tracks record audio, the MIDI-in target records MIDI. Behavior
   change, recorded rather than silent.
8. **MIDI recording requires no audio input device.** A take with only a MIDI
   target opens no input stream, spawns no disk writer, and does not touch
   `gen_maps`. `stop_recording` succeeds when either half is running.
9. **MIDI-in timestamps are transport-position-at-arrival.** The midir
   callback stamps each event with `SharedRt::position`, which advances once
   per audio block (~5–11 ms at typical buffer sizes), plus midir's own
   delivery latency. No `stamp_us`-based sub-block placement in this slice.
   Recorded; the follow-up (use midir's `stamp_us` + a block-start wall-clock
   anchor to place events inside the block) is named in the handoff.
10. **Note-out is a routing carve-out, not a track field.** A per-track
    "external instrument" target would be a new document field, a new op and
    an `OP_FORMAT_VERSION` bump — the backlog itself calls that a separate,
    bigger cut. This slice ships a single app-config "route this MIDI track's
    notes to the output port" selection (same carve-out as ruling 1), so the
    owner gets note-out now without a format change. The track keeps sounding
    internally too; muting it in AURA is the documented way to avoid
    doubling. The document-model version stays deferred.
11. **No persistence of the selected ports/target across restarts.** Slice 1's
    port id is `"<name>#<index>"` and is explicitly not durable across replug
    or reboot, so persisting it can silently select the *wrong* device.
    Deferred until port ids are stable; recorded (slice 1's module-doc
    "Slice-2 TODO" is answered with this ruling, not with silence).
12. **No new MCP tools.** The roster stays frozen (ARCHITECTURE §12.2) —
    Plan E ruling 6, carried forward. Every seam added here is a
    `ControlPlane` method, so a future MCP tool is a one-liner.
13. **Dated counts are corrected in Task 1 and finalized in Task 12, not
    churned per task.** README.md:389/CONTRIBUTING.md:62 say 506 while the
    tree is at 527 (PR #17's omission). Task 1 sets them to the verified
    527/206; Task 12 sets the final numbers. Intermediate tasks do not touch
    them — same practice Plan E used (its Task 17 step 5), recorded so the
    convention's spirit (counts are never stale at a merge boundary) is kept
    without twelve one-line README commits.

## Non-goals (so the diff stays reviewable)

- No per-track "external instrument" document field / no new op / no
  `OP_FORMAT_VERSION` bump (ruling 10).
- No MIDI **thru** (keyboard → external port while stopped). Named here so
  it is not silently absent; it is a two-line addition to the out thread once
  someone asks for it.
- No CC / pitch-bend / aftertouch / program-change in or out — notes only
  (plus clock/transport). The parser and the ring carry a `kind` byte, so
  adding them later is additive.
- No quantize / count-in / metronome on the recorded take (the roadmap's own
  separate Tier-1 items).
- No loop-aware overdub or take comping — one take, one clip.
- No MIDI-out latency offset preference (the external gear runs early by
  roughly AURA's output buffer latency; documented, not compensated).
- No sub-block MIDI-in timestamping (ruling 9).
- No JACK transport / Ableton Link (backlog's path (b), later).
- No change to `engine::rebuild`'s session-read path — that is Track A's, and
  this plan is deliberately shaped to stay out of it.

```rust
//! Hardware MIDI-in seam (slice 2). Owns the wait-free path from the midir
//! callback thread to the RT audio callback, the resolved target slot, and
//! the control-side take capture buffer. Knows nothing about midir, ports,
//! ops or the document.

pub const EV_NOTE_OFF: u8 = 0;
pub const EV_NOTE_ON: u8 = 1;
pub const EV_ALL_OFF: u8 = 2;

/// POD, `Copy`, 3 bytes — this crosses an rtrb ring into the RT callback.
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub struct LiveMidiEvent { pub kind: u8, pub key: u8, pub velocity: u8 }

impl LiveMidiEvent {
    pub fn note_on(key: u8, velocity: u8) -> Self;
    pub fn note_off(key: u8) -> Self;
    pub fn all_off() -> Self;
}

/// One captured incoming edge, stamped with the transport position observed
/// when it ARRIVED (ruling 9). Control-side only — never crosses to RT.
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub struct CapturedEvent { pub sample: u64, pub on: bool, pub key: u8, pub velocity: u8 }

/// A finished take's raw capture (see `midi::capture` for the conversion).
#[derive(Debug, Clone, PartialEq, Eq)]
pub struct Capture {
    pub track_id: String,
    pub start_sample: u64,
    pub end_sample: u64,
    pub events: Vec<CapturedEvent>,
}

/// Ring depth: one block of dense playing is a handful of events; 256 is
/// ~5 s of very fast playing at 60 Hz drain, so overflow means the audio
/// callback stopped, not that the player is fast.
pub const LIVE_IN_RING_SLOTS: usize = 256;
/// Most events one RT block will take from the ring (preallocated array on
/// the callback side — never an allocation).
pub const MAX_LIVE_IN_PER_BLOCK: usize = 64;
/// `target_slot` sentinel: nothing routed.
pub const NO_SLOT: u32 = u32::MAX;

#[derive(Default)]
pub struct MidiInHub { /* private */ }

impl MidiInHub {
    pub fn new() -> Self;
    /// Called once by `audio::init`; used only to stamp captured events.
    pub fn attach_shared(&self, shared: Arc<SharedRt>);

    // -- producer side (midir callback thread; non-RT, may lock) ----------
    pub fn install_producer(&self, tx: rtrb::Producer<LiveMidiEvent>);
    pub fn clear_producer(&self);
    /// Never blocks on the RT side; returns false (and bumps `dropped`) when
    /// no producer is installed or the ring is full.
    pub fn push(&self, ev: LiveMidiEvent) -> bool;
    pub fn dropped(&self) -> u64;

    // -- target (control side) --------------------------------------------
    /// Push an `all_off` for the OUTGOING target first, then switch. Marks
    /// the resolution dirty so the next `refresh_target` re-resolves.
    pub fn set_target_track(&self, track_id: Option<String>);
    pub fn target_track(&self) -> Option<String>;
    pub fn has_target(&self) -> bool;
    /// Engine control thread, once per loop tick. Re-resolves only when the
    /// target changed or the graph generation moved. Takes ONLY the tables
    /// lock (never the session lock) — [C1] order is preserved trivially.
    pub fn refresh_target(&self, generation: u64, tables: &SharedGraphTables);
    /// RT-side read: a single relaxed atomic load, no lock, no allocation.
    pub fn target_slot(&self) -> Option<usize>;

    // -- take capture (control side) ---------------------------------------
    pub fn begin_capture(&self, track_id: String, start_sample: u64);
    pub fn capturing(&self) -> bool;
    /// Called from the midir callback thread; stamps with `SharedRt::position`
    /// (0 when no `SharedRt` is attached, i.e. in unit tests). No-op when not
    /// capturing.
    pub fn capture_event(&self, on: bool, key: u8, velocity: u8);
    /// Disarms and returns the take. `end_sample` is the position now.
    pub fn end_capture(&self) -> Option<Capture>;
}

/// Process-global hub (same shape as `sampler::registered_bank` and
/// `midi::playback::registered_store`): lazily created, never replaced.
pub fn hub() -> &'static Arc<MidiInHub>;
```

Implementation notes the implementer must honor:
- Internals: `tx: Mutex<Option<rtrb::Producer<LiveMidiEvent>>>`,
  `dropped: AtomicU64`, `target: Mutex<Option<String>>`,
  `target_dirty: AtomicBool`, `target_slot: AtomicU32` (init `NO_SLOT`),
  `resolved_generation: AtomicU64`, `capture: Mutex<Option<CaptureState>>`,
  `shared: OnceLock<Arc<SharedRt>>`. Use `parking_lot::Mutex` (the crate's
  house mutex).
- `refresh_target`:
  ```rust
  let dirty = self.target_dirty.swap(false, Relaxed);
  if !dirty && self.resolved_generation.load(Relaxed) == generation { return; }
  let want = self.target.lock().clone();
  let slot = match &want {
      None => NO_SLOT,
      Some(id) => tables.lock().slots.get(id.as_str()).copied()
          .map(|s| s as u32).unwrap_or(NO_SLOT),
  };
  self.target_slot.store(slot, Relaxed);
  self.resolved_generation.store(generation, Relaxed);
  ```
- `set_target_track`: if a target was set and the new one differs, `push`
  `LiveMidiEvent::all_off()` **before** replacing, so the old node releases
  its voices; then store, then `target_dirty.store(true, Relaxed)`.
- `push` locks the producer mutex — legal here (midir's callback thread is
  NOT the RT thread; slice 1 already locks a mutex in `record_event`). The
  RT side never touches this mutex: it owns the `Consumer` half.

fn push_without_a_producer_is_dropped_not_a_panic() {
    let hub = MidiInHub::new();

#[test]
fn push_and_pop_round_trip_through_the_ring() {
    let hub = MidiInHub::new();
    let (tx, mut rx) = rtrb::RingBuffer::new(LIVE_IN_RING_SLOTS);
    hub.install_producer(tx);
    assert!(hub.push(LiveMidiEvent::note_on(60, 100)));
    assert!(hub.push(LiveMidiEvent::note_off(60)));
    assert_eq!(rx.pop().unwrap(), LiveMidiEvent { kind: EV_NOTE_ON, key: 60, velocity: 100 });
    assert_eq!(rx.pop().unwrap(), LiveMidiEvent { kind: EV_NOTE_OFF, key: 60, velocity: 0 });
    assert_eq!(hub.dropped(), 0);
}

#[test]
fn ring_overflow_counts_drops_and_never_blocks() {
    let hub = MidiInHub::new();
    let (tx, _rx) = rtrb::RingBuffer::new(4);
    hub.install_producer(tx);
    for i in 0..10u8 { hub.push(LiveMidiEvent::note_on(i, 100)); }
    assert!(hub.dropped() >= 6, "dropped {} of 10 into a 4-slot ring", hub.dropped());

#[test]
fn switching_target_emits_an_all_off_for_the_old_node() {
    let hub = MidiInHub::new();
    let (tx, mut rx) = rtrb::RingBuffer::new(8);
    hub.install_producer(tx);
    hub.set_target_track(Some("t-1".into()));
    assert!(rx.pop().is_err(), "no all-off when nothing was routed yet");
    hub.set_target_track(Some("t-2".into()));

    hub.set_target_track(None);
    assert_eq!(rx.pop().unwrap().kind, EV_ALL_OFF);

#[test]
fn refresh_target_resolves_the_slot_from_the_current_tables() {
    let hub = MidiInHub::new();
    let tables = crate::audio::rt::GraphTables::empty();
    tables.lock().slots.insert("t-1".into(), 3);
    tables.lock().generation = 1;
    hub.set_target_track(Some("t-1".into()));
    hub.refresh_target(1, &tables);
    assert_eq!(hub.target_slot(), Some(3));

#[test]
fn refresh_target_is_a_noop_within_the_same_generation() {
    let hub = MidiInHub::new();
    let tables = crate::audio::rt::GraphTables::empty();
    tables.lock().slots.insert("t-1".into(), 3);
    hub.set_target_track(Some("t-1".into()));
    hub.refresh_target(7, &tables);
    assert_eq!(hub.target_slot(), Some(3));
    // Slot map changes without a generation bump: NOT re-read (the engine
    // bumps `generation` on every rebuild, so this cannot go stale in
    // production — this pins that the fast path really is a fast path).
    tables.lock().slots.insert("t-1".into(), 9);
    hub.refresh_target(7, &tables);
    assert_eq!(hub.target_slot(), Some(3));
    // A new generation re-resolves.
    hub.refresh_target(8, &tables);
    assert_eq!(hub.target_slot(), Some(9));
}

    pub notes: Vec<MidiNote>,
    /// Watermark for the new clip: `notes.len() as u32 + 1` (ADR 0001 —
    /// ids start at 1 and are never reused).
    pub next_note_id: u32,
    /// Absolute placement of the take on the timeline.

    /// Take length in ticks, always >= 1.

Rules (each has a test below):
- `start_ticks = map.samples_to_tick(capture.start_sample)`; a note's tick is
  `map.samples_to_tick(ev.sample).saturating_sub(start_ticks)`, cast to `u32`
  with `u32::try_from(..).unwrap_or(u32::MAX)`.
- A note-on for a key already sounding closes the previous note at the new
  tick (retrigger) and opens a fresh one.
- A note-off with no matching note-on is ignored.
- Note-ons still sounding at the end are closed at the take end tick
  (`map.samples_to_tick(capture.end_sample) - start_ticks`).
- Length is clamped to `>= 1` tick (a note that opens and closes inside one
  tick still exists).
- Velocity is clamped to `1..=127` (`MidiNote::validate`'s range);
  channel is `0`.
- Note ids are minted `1..=n` in output order; `next_note_id = n + 1`.
- Notes are sorted by `(tick, key)` — the invariant `MidiClip.notes` carries.
- `length_ticks` = `max(1, take_end_ticks - start_ticks, last_note_end)`.
- Clip fields: `id: uuid::Uuid::new_v4().to_string().into()`,
  `track_id: capture.track_id.clone().into()`, `name: name.to_string()`,
  `timeline_start_ticks: start_ticks`, `length_ticks`,
  `next_note_id`, `content_id: ContentId::mint()`,
  `lane_id: LaneId::default_for_track(&capture.track_id)`,
  `content_length_ticks: None` — the exact field set
  `midi::midi_add_clip_core` builds (every non-serde constructor must set
  `content_id`/`lane_id` explicitly; see `MidiClip`'s doc).

```rust
//! MIDI output: transport sync (clock/Start/Stop/Continue/SPP) and note-out
//! to external gear. Runs entirely off `SharedRt` atomics + a document
//! snapshot on its own non-RT thread — see ruling 3: NOTHING here touches
//! `audio/engine.rs`.

/// One outbound MIDI message. POD so the clock and the note scheduler share
/// one output buffer.
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub struct OutMsg { pub bytes: [u8; 3], pub len: usize }

impl OutMsg {
    pub fn one(b: u8) -> Self;
    pub fn three(a: u8, b: u8, c: u8) -> Self;
    pub fn as_slice(&self) -> &[u8];
}

#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum ClockMsg { Clock, Start, Continue, Stop, SongPosition(u16) }

impl ClockMsg {
    /// 0xF8 clock, 0xFA start, 0xFB continue, 0xFC stop,
    /// 0xF2 lsb msb song position (14-bit, 7 bits per byte).
    pub fn to_out(self) -> OutMsg;
}

/// MIDI clock is 24 pulses per quarter note, always — independent of ppq.
pub const PULSES_PER_QUARTER: u64 = 24;
/// Most clock pulses emitted in one tick; a bigger gap means the thread was
/// starved or the transport jumped, and is re-anchored instead of flooded.
pub const MAX_PULSE_BURST: u64 = 24;
/// Position deviation (in samples) that counts as a transport JUMP rather
/// than ordinary block quantization: 20 ms at the engine rate.
pub fn drift_tolerance(rate: u32) -> u64 { (rate as u64) / 50 }

pub fn pulse_of_tick(tick: u64, ppq: u32) -> u64;
/// SPP counts MIDI beats (sixteenth notes) = 6 clock pulses; 14-bit range.
pub fn song_position_of_pulse(pulse: u64) -> u16;

/// What the driver reads each tick.
pub struct ClockInput<'a> {
    pub now_micros: u64,
    pub playing: bool,
    pub position: u64,
    pub rate: u32,
    pub map: &'a TempoMap,
}

#[derive(Default)]
pub struct ClockEngine { /* private */ }

impl ClockEngine {
    pub fn new() -> Self;
    /// Append this tick's messages. Pure with respect to `now_micros` — the
    /// caller owns the clock, so tests drive it deterministically.
    pub fn step(&mut self, input: ClockInput<'_>, out: &mut Vec<ClockMsg>);
    /// The interpolated sample position this tick resolved to (Task 8's note
    /// scheduler advances over the same window, from ONE anchor).
    pub fn estimated_sample(&self) -> u64;
    pub fn running(&self) -> bool;
    pub fn pulses_sent(&self) -> u64;
    pub fn resyncs(&self) -> u64;
}
```

`step`'s state machine (each clause has a test):
1. `!playing`: if it was running → push `Stop`, clear the anchor, `running =
   false`. Otherwise nothing.
2. `playing` and not running (**transport start**): anchor `(position,
   now_micros)`; `pulse = pulse_of_tick(map.samples_to_tick(position), map.ppq())`;
   `last_pulse = pulse`; push `Start` when `pulse == 0`, else
   `SongPosition(song_position_of_pulse(pulse))` followed by `Continue`.
   `running = true`.
3. `playing` and running: estimate
   `est = anchor.sample + (now_micros - anchor.micros) * rate / 1_000_000`.
   If `position.abs_diff(est) > drift_tolerance(rate)` → **jump**: push
   `Stop`, re-anchor at `(position, now_micros)`, recompute the pulse, push
   `SongPosition` + `Continue`, `resyncs += 1`, return (ruling 5).
   Otherwise keep the anchor (interpolation is authoritative between
   blocks — the observed `position` only moves once per audio block).
4. `pulse = pulse_of_tick(map.samples_to_tick(est), ppq)`;
   `n = pulse - last_pulse`; if `n > MAX_PULSE_BURST` just re-anchor
   `last_pulse = pulse` (no flood); else push `n` × `Clock` and advance
   `last_pulse`. `pulses_sent += n`.

Thread contract (write this as a module-doc paragraph, it is the reviewable
part):
- Named `aura-midi-out`, spawned on first `select_port(Some(..))`, stopped by
  an `Arc<AtomicBool>` on close/`Drop`. **Not an RT thread**: it may allocate
  and lock.
- Loop: `std::thread::sleep(Duration::from_micros(500))`, then one
  `tick(now_micros, shared.playing, shared.position, shared.sample_rate)`.
  500 µs gives < 1 ms clock jitter at any tempo; at 120 bpm a pulse is
  20.8 ms apart, so the loop is ~40× oversampled.
- Tempo snapshot: at most every **250 ms**, `session.try_lock()` (never a
  blocking lock — `engine::rebuild` holds the session across a graph build
  and would stall the clock); on success rebuild the `TempoMap` from
  `session.midi.ppq` + `session.midi.tempo_events` + the engine rate ONLY if
  they changed. A contended try_lock simply keeps the previous snapshot.
  Consequence, documented: a tempo edit reaches external gear within ~250 ms.
- Lock order: this thread takes the session lock and NOTHING else, and never
  issues an `EngineHandle::request` — so the Committer deadlock invariant
  ("no thread may hold the session lock across a `request`") holds trivially.
- On stop/close: send `ClockMsg::Stop` before dropping the connection so the
  slave does not run on forever.
- `set_clock_enabled(false)` suppresses clock/transport bytes but leaves the
  thread and the port alive (Task 8's note-out keeps working).
- Extract the per-tick body as
  `pub(crate) fn out_tick(engine: &mut ClockEngine, sink: &mut dyn ClockSink, input: ClockInput<'_>, clock_enabled: bool) -> Result<(), String>`
  so it is testable with an injected sink and injected time.

    /// this slice.

#[derive(Default)]
pub struct NoteOutEngine { /* cursor, sounding: [bool; 128], notes_sent */ }

impl NoteOutEngine {
    pub fn new() -> Self;
    /// Emit note messages for the half-open sample window `[from, to)`.
    pub fn advance(&mut self, snap: &NoteOutSnapshot, from: u64, to: u64, out: &mut Vec<OutMsg>);
    /// Release everything currently sounding (transport stop, resync, track
    /// change, port close). Emits one Note Off per sounding key — explicit
    /// offs, not just CC 123, because not every device honors All Notes Off.
    pub fn all_off(&mut self, channel: u8, out: &mut Vec<OutMsg>);
    /// `all_off` + reposition the cursor to the first event at or after
    /// `to` (a seek / loop wrap / fresh start).
    pub fn reseek(&mut self, snap: &NoteOutSnapshot, to: u64, out: &mut Vec<OutMsg>);
    pub fn notes_sent(&self) -> u64;
}

Wire form: note on = `[0x90 | ch, key, velocity]`, note off =
`[0x80 | ch, key, 0]`. An `AbsNoteEvent` with `velocity == 0` IS the note-off
(the convention `playback::track_events` produces).
